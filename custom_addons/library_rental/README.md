# Library Rental

## Обрана структура зв’язків і чому

`library.member` — окрема модель з ім’ям і унікальним номером читацького квитка. Це дає змогу вести читачів незалежно від контактів Odoo, тому модулю не потрібна залежність `contacts`.

`library.book` має зв’язок One2many із примірниками. У `library.copy.book_id`, `library.loan.copy_id` і `library.loan.member_id` використано `ondelete="restrict"`: видалення книги, примірника або читача, на яких посилаються облікові записи, не повинно мовчки знищувати примірники чи історію видач. Унікальність номера читацького квитка забезпечується обмеженням БД. ORM constraint не дозволяє створити більше однієї активної видачі для того самого примірника.

## Відхилення від рекомендованої структури

Відхилень немає. Модуль має `models/`, `views/`, `security/` і `demo/`; каталог `data/` наразі не потрібен.

## Що зроблено без правок

- Додано моделі книг, примірників, читачів і видач.
- Додано доступи, спискові й формові подання, меню та демо-дані.
- Для демо-даних прострочена дата обчислюється від поточної дати під час встановлення.

## Що потребує ручної перевірки

Перевірте обов’язковість полів і правила видалення Many2one:

| Поле | Обов’язкове | `ondelete` | Що перевірити |
|---|---:|---|---|
| `library.copy.book_id` | так | `restrict` | Книгу з примірниками не можна видалити |
| `library.loan.copy_id` | так | `restrict` | Примірник з історією видач не можна видалити |
| `library.loan.member_id` | так | `restrict` | Читача з історією видач не можна видалити |

## Практика ORM у `odoo-bin shell -d <база>`

Замініть `<база>` на назву бази даних. Команди нижче виконуються в Odoo shell; у місцях із `...` підставте реальні ідентифікатори або значення з вашої бази.

### Знайти книги автора через домен

```python
books = env["library.book"].search([("author", "=", "Robert C. Martin")])
books.mapped("name")
```

Очікується список назв книг цього автора, наприклад `["Clean Code"]`, якщо встановлені демо-дані.

### Порахувати вільні примірники книги через домен

```python
book = env["library.book"].search([("name", "=", "Clean Code")], limit=1)
active_copy_ids = env["library.loan"].search([
    ("state", "=", "active"),
]).mapped("copy_id").ids
free_copies = env["library.copy"].search([
    ("book_id", "=", book.id),
    ("id", "not in", active_copy_ids),
])
len(free_copies)
```

Очікується кількість примірників обраної книги, для яких немає активної видачі; у демо для `Clean Code` буде `1`.

### Порахувати вільні примірники циклом по recordset

```python
free_count = 0
for copy in book.copy_ids:
    active_loan = env["library.loan"].search_count([
        ("copy_id", "=", copy.id),
        ("state", "=", "active"),
    ])
    if not active_loan:
        free_count += 1
free_count
```

Очікуваний результат той самий, що й у варіанті з доменом.

### Знайти прострочені активні видачі

```python
from odoo import fields

overdue_loans = env["library.loan"].search([
    ("state", "=", "active"),
    ("due_date", "<", fields.Date.today()),
])
overdue_loans
```

Серед результатів буде принаймні одна демо-видача з простроченим терміном повернення.

### Створити видачу та одразу закрити її

```python
from odoo import fields

loan = env["library.loan"].create({
    "copy_id": ...,  # ID вільного примірника
    "member_id": ...,  # ID читача
    "due_date": fields.Date.today(),
})
loan.write({
    "state": "returned",
    "return_date": fields.Date.today(),
})
loan.state, loan.return_date
```

Створення вдасться лише для примірника без активної видачі; після `write()` очікується `("returned", сьогоднішня дата)`.
